# Clean on-dark IB Bridge logo in hero and footer, plus social/OG assets

The change makes the IB Bridge logo more present on the dark surfaces of the landing page. A new `logo-ondark.png` variant is generated by a hue-based recolor that whitens only the navy "IB" wordmark and tagline while leaving the teal "Bridge" lettering and bridge arcs untouched, so the mark reads cleanly on the hero gradient and footer navy without the previous white chip/box. The hero and footer now use this variant box-free, the navbar keeps the original colored `logo.png`, and the change adds OG/Twitter meta plus a 1200×630 `og-image.png` and regenerated favicons. Bilingual attributes, the language switcher, mobile nav, and a11y labels are preserved, and both desktop and mobile report no horizontal overflow. **Watch for:** nothing blocking — the on-dark glyph quality, color split, box-free placement, and asset dimensions all verify against the saved evidence (confirmed).

## On-dark recolor keeps teal exact while whitening the navy mark

The core move is a hue-based classification in `make_ondark.py`: opaque pixels are split by the green-minus-red gap, so blue-dominant navy pixels (the "IB" glyphs and tagline) ramp toward near-white `#F3F7F8` while teal-family pixels (`gr >= 25`) are held unchanged behind a hard guard. The alpha channel is copied byte-for-byte, preserving the 1536×1024 source transparency. This is the right axis to classify on — brightness thresholding would have bled the teal, but a hue gate separates the two ink families cleanly, which is borne out by the verifier's 0.000% teal delta and the dark-navy count collapsing from 30577 to 1 (confirmed).

The eye-test composite over `#12293f` confirms the pixel stats translate to a clean render: the "IB" is solid white with sharp edges, no navy halo around the glyphs, and no patchy interior; "Bridge" and both arcs stay teal; the tagline reads light and legible. The hero and footer crops show the same mark blending into the live gradient and the navy-deep footer with no visible seam (confirmed).

```
         navy "IB" + tagline  -->  near-white (#F3F7F8)
logo.png -------------------------------------------------> logo-ondark.png
         teal "Bridge" + arcs -->  unchanged (gr>=25 guard)
         alpha                -->  copied byte-for-byte
```

## Box-free placement and dead-CSS cleanup

Both the hero and footer previously wrapped the logo in a `<div>` (`.hero-logo-wrap`, `.footer-brand`) that carried the margin and, in the earlier white-chip iteration, the visible box. Those wrappers are removed from the markup and the orphaned rules deleted from `styles.css`; the margin moves onto the `.hero-logo` / `.footer-logo` rules themselves. The hero logo is 120px desktop and 90px mobile (within the ~110-130 / ~84-96 targets), centered above `.hero-pill`; the footer logo is 56px centered above the teal `.footer-tag`, which is untouched. The navbar still points at the colored `logo.png`.

The apparent overlap of the hero logo with the navbar in `hero-mobile.png` is a crop artifact, not a layout bug: `.site-header` is `position: sticky; top: 0`, so it stays in document flow and the hero's `56px` top padding sits the mark below it on the live page — the sticky header only overlays during an element-region screenshot crop (confirmed via styles.css).

## Social, OG, and favicon assets

`og-image.png` is exactly 1200×630 with the colored (not on-dark) logo centered on a light `#f3f7f8` field. OG and Twitter `summary_large_image` meta tags are added to `<head>` with absolute `duarteopdiniz-gif.github.io/ib-bridge/` URLs for both the page and the image — the absolute form matters on GitHub Pages, where relative image URLs would not resolve in social scrapers. Favicons regenerate to 32×32 and 180×180 from the alpha-bbox crop (confirmed by Pillow dimension read).

## Bilingual, nav, and a11y integrity

`data-en` and `data-es` both count 88, matching the pre-change balance, and the two on-dark logo `<img>` elements carry no `data-*` attributes, so the language switcher cannot swap them — the recorded evidence shows the hero logo `src` staying `logo-ondark.png` across an ES toggle. Alt text on both logos is static and meaningful, the brand link keeps its `aria-label`, and the nav toggle keeps `aria-expanded`/`aria-controls` with the recorded open behavior intact. The stylesheet cache-bust appears exactly once, bumped to `v=20260923b` (confirmed).
